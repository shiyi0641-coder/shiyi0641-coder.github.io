01 / BACKGROUND

招新不是“信息发布”，而是一个匹配问题

传统社团招新通常是单向的信息展示。 新生需要主动寻找社团，社团也需要人工筛选学生。 两边都在承担本可以由系统解决的信息匹配成本。

对新生而言，社团信息往往分散在海报、公众号和线下宣传中。 当可选择的社团数量增加后，学生很难快速判断哪些社团真正符合自己的兴趣， 容易陷入大量浏览和比较。

对社团管理者而言，传统的纸质表格或零散问卷无法形成完整的招新数据闭环。 从收集报名信息到筛选、通知面试、记录录取状态，都需要大量人工操作。

因此，这个产品没有把核心定义成“社团信息平台”， 而是将问题重新定义为一个双边匹配问题： 让合适的学生更快找到合适的社团，同时让社团主动发现合适的学生。

02 / PROBLEM

两端用户，两个核心问题

产品同时服务 C 端新生与 B 端社团，因此没有只解决其中一侧的效率问题。

C-SIDE / STUDENT

新生找不到“适合自己的”

核心问题不是没有社团，而是选择太多、信息太散， 学生缺少一个能够理解自己兴趣的筛选机制。

  • 社团信息高度碎片化
  • 面对大量社团产生选择困难
  • 缺少个性化推荐
  • 重复填写报名信息
B-SIDE / CLUB

社团找不到“真正匹配的”

社团需要的不只是更多报名者，而是与自身需求和兴趣标签相匹配的学生。

  • 人工筛选报名信息成本高
  • 面试邀约依赖人工通知
  • 招新状态难以统一追踪
  • 缺少主动触达候选人的机制
PRODUCT POSITIONING
双边市场智能匹配引擎 + 社团全生命周期管理工具

C 端通过兴趣标签建立用户画像， 系统根据兴趣契合度生成推荐信息流； B 端通过期望标签定义社团需求， 并使用招新看板管理从申请到录取的完整流程。

07 / VALUE

从一次招新，延伸到完整参与链路

产品价值不只是提高报名效率，而是让匹配、报名和后续管理形成连续的数据闭环。

01

降低发现成本

通过兴趣标签与推荐排序， 将新生发现合适社团的时间从数天压缩到几分钟。

02

降低报名摩擦

复用用户画像， 通过一键报名减少重复填写和信息输入。

03

提高管理效率

将筛选、邀约、面试和录取状态集中到统一看板， 降低社团管理成本。

08 / MY ROLE

我的工作

我负责从用户需求出发定义双边产品结构， 并将匹配机制和招新流程转化为可执行的产品方案。

  • 分析 C 端新生与 B 端社团管理者的双边需求
  • 定义产品定位、用户角色与核心业务目标
  • 设计兴趣标签采集与用户画像建立流程
  • 设计基于兴趣标签和社团期望标签的匹配机制
  • 规划推荐信息流、匹配度展示和一键报名流程
  • 设计 B 端拖拽式招新看板与状态流转
  • 设计自动邀约、通知和社团招新配置等自动化能力
  • 通过统一标签字典解决双边数据结构不一致问题
  • 输出完整 PRD、业务流程与页面交互方案
PRODUCT THINKING

推荐系统的核心不是“推荐”， 而是建立双方都愿意使用的数据基础。

这个项目中最重要的产品设计并不是单独做一个推荐列表， 而是同时设计学生兴趣标签和社团需求标签， 再通过统一标签体系建立双方可以被计算和比较的数据结构。 在此基础上，推荐、主动邀约和招新流程管理才可以形成完整闭环。
